# 许可与合规说明

## 本项目用什么许可证

**AGPL-3.0-or-later**（GNU Affero General Public License v3 或更高版本）

完整正文见仓库根目录的 `LICENSE`。

## 为什么是 AGPL 而不是 GPL

GPL 的义务只在**分发**软件时触发 ✗
→ 有人把 WARDEN 放到服务器上做成"在线拦截服务"，就不算分发，可以完全不开源 ✗
→ 这正好是 GPL 最大的漏洞

AGPL 第 13 条（Remote Network Interaction）把义务扩展到**网络交互**：
只要你让用户通过网络使用它，就必须提供完整源码 ✓

WARDEN 本身不联网 ✓ 但这个条款堵住了"云端规避"这条路 ✓

## 第三方依赖（合规角度的好消息）

**零第三方依赖** ✓

| 项目 | 说明 |
|---|---|
| .NET 运行时 / BCL | 微软官方，MIT 许可，与 AGPL 兼容 ✓ |
| Win32 API | 操作系统接口，不涉及许可 ✓ |
| OpenCC | ★ **只在开发时**用来生成繁体语言包 ✓ **没有打包进程序** ✓ |
| BouncyCastle / Markdig 等 | 讨论过但**没有引用** ✓ 保持了零依赖 ✓ |

→ 没有第三方代码需要额外声明，也没有许可冲突 ✓

## 打包时必须带上什么

安装包 / 便携包里必须包含：

* `LICENSE`（AGPL-3.0 全文）—— 少了这个就是违规 ✗
* `README.md`（说明与来源）

`build.ps1` 已经把这两个文件复制进 `dist\app\` ✓ 安装器载荷随之带上 ✓

## 如果以后想加第三方库

1. 先看它是不是与 AGPL 兼容（MIT / BSD / Apache-2.0 都可以 ✓）
2. 不兼容的（例如把 GPL-2.0-only 混进来 ✗）不要用
3. 加完更新本文件，写明库名、版本、许可、来源 ✓

## 给别人分发时的提醒

* 你改过 WARDEN 再分发 → 必须把改动也按 AGPL 开源 ✓
* 你把它做成在线服务 → 同样必须提供源码 ✓（第 13 条）
* 只要提供源码链接 / 副本给使用者就行，不必交给原作者 ✓

## 数字签名与许可证无关

签名证书只证明"这个 exe 是谁编译的" ✓
不改变许可证条款 ✓ 也不代表作者为你背书 ✓
