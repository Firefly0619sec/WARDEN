**Description**\*（一段话，别列版本号与依赖）

```
WARDEN is a free, open-source Windows utility that identifies and suppresses
intrusive popups. Instead of matching window titles or shipping an ad-signature
list that goes stale, it scores observable behaviour: how often a window is
created, whether it repeatedly steals focus, whether it contains input boxes or
child controls, whether it is a small floating panel, whether it churns its
title, and whether it returns after being closed. Only windows above a
user-controlled threshold are acted on, and the escalation is deliberate -
ask the window to close, hide it, and only then consider force-killing it if the
user has allowed that. Processes carrying a valid code signature, or listed on
the user's whitelist, are never hard-killed. The program runs completely
offline, needs no account, collects nothing, writes an auditable local log of
everything it does, and keeps evidence (with usernames masked) on the user's own
machine. It ships with six interface languages and is built as a Native AOT
single executable with no third-party dependencies.
```

**Reputation**\*（★ 这条要诚实 ✗ 我们项目还很新）

```
WARDEN is a new project - it reached public beta (0.1.0-beta.1) in October 2026,
so there is no media coverage or download history yet. What can be verified
today:

* Public repository with full source, build script and CI:
  https://github.com/Firefly0619sec/WARDEN
* Every commit is GPG-signed; the repository history is public and auditable.
* GitHub Actions pipeline builds every push (.github/workflows/build.yml).
* The project documents its threat model, its safety design and its licence
  reasoning in-tree (docs/设计说明.md, docs/许可与合规.md).
* It has an automated behavioural test suite that drives a purpose-built rogue
  window simulator and asserts, among other things, that whitelisted processes
  are never force-killed and that out-of-scope processes are never touched.
* Real-world usage so far is the maintainer's own machines plus testers
  recruited from a small community; feedback is collected through the
  repository's issue templates.

We are applying at this early stage deliberately: unsigned binaries are exactly
the problem this tool exists to solve, and SmartScreen currently warns on every
download.
```
