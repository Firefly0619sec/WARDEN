# F1 蓝牙靠近感知 —— 探针结论与方案

> 探针时间：2026-10-13　目标机器：ThinkPad T420（Windows 10）

## 一、实测结论（先说坏消息 ✗）

```
① 蓝牙无线电状态：Generic Bluetooth Radio  →  【Error】✗
   → 驱动没装好/不匹配 ✗ 现在这台机器上蓝牙根本不可用 ✓

② 已连接的蓝牙设备（BTHENUM 枚举）：0 个 ✗
   → 没有手机/耳机/手环连着 ✓ 也就没有"在/不在"可判断 ✓

③ 能不能取到信号强度（RSSI）：
   Windows 没有现成的 RSSI WMI 类 ✗（MSFT_BluetoothSignalStrength 不存在 ✓）
   → ★ 结论：F1【做不了"距离 3 米"这种连续判断】✗
     只能做【在 / 不在】两态 ✓（设备连着 = 人在；断开 = 人走了 ✓）
```

## 二、所以 F1 的可行形态（改成两态 ✓）

```
配置里加一段 presence ✓

  "presence": {
    "enabled": true,
    "device": "你的手机名字 或 蓝牙设备名",
    "pause_when_away": true,      // 设备断开 → 自动暂停守护 ✓
    "resume_delay_sec": 20        // 回来 20 秒后才恢复（防抖 ✓）
  }

行为：
  · 每 30 秒查一次配置里那个蓝牙设备在不在 ✓
  · 不在 → 自动切"暂停"（托盘变黄 ✓）并在日志写一条 ✓
  · 回来 → 延迟 N 秒后自动恢复（避免信号抖动来回切 ✓）
  · 全程记日志 ✓ 且默认关闭（enabled=false ✓ 不打扰现有用户 ✓）
```

## 三、前置条件（必须先解决 ✗）

```
☐ 先让 T420 的蓝牙能用起来 ×
    · ThinkPad T420 的内置蓝牙是 Broadcom，Win10 常缺驱动 ✗
    · 需要装 Lenovo 官方蓝牙驱动（或 Broadcom 的 Win10 驱动 ✓）
    · 装好后「设备管理器」里 Generic Bluetooth Radio 应显示正常 ✓
☐ 然后配一个"随身设备"（手机/手环 ✓）与电脑配对 ✓
☐ 配对后跑一次探针确认它在 BTHENUM 列表里状态为 OK ✓ 再动手写代码 ✓
```

## 四、实现要点（等驱动好了就开工 ✓）

```
· 查询方式（主程序是 AOT ✗ 不能引 WMI 那套 ✗）：
    用 SetupAPI P/Invoke 枚举 BTHENUM 设备 ✓
      SetupDiGetClassDevs / SetupDiEnumDeviceInfo / SetupDiGetDeviceRegistryProperty ✓
    比对设备名 → 判断在/不在 ✓
    （备选：调用 DeviceIoControl 问蓝牙驱动 ✓ 但复杂 ✗ 先用 SetupAPI ✓）
· 复用已有机制：暂停 = 设置 TrayIcon 状态 + 主循环跳过扫描 ✓（已就绪 ✓）
· 配置项加进 GuardConfig ✓ 设置界面「保护」页加一个开关 + 设备名输入框 ✓
· 语言包补 5~8 条文案（六语言 ✓ 机制已就绪 ✓）
· 测试：拔掉/关掉那个设备的蓝牙 → 看日志与托盘颜色是否按预期变 ✓
```

## 五、如果驱动实在装不上（退路 ✓）

```
① 用 USB 蓝牙小适配器（几十块 ✓ Win10 免驱 ✓）→ 同样的方案照样能用 ✓
② 或者换判据：不用蓝牙，改用"锁屏/解锁"事件 ✓
     Win+L 锁屏 → 视为离开；解锁 → 视为回来 ✓
     ★ 这个不需要任何额外硬件 ✓ 而且更可靠 ✓
     代价：只有主动锁屏才触发（挂着不锁就不算离开 ✗）
   → 我建议：两个判据都实现，配置里选 ✓（蓝牙优先，锁屏兜底 ✓）
```

---

**一句话总结**：F1 的软件方案已经定好了 ✓（两态 + 锁屏兜底 ✓）
但**当前这台 T420 的蓝牙是 Error 状态** ✗ 硬件/驱动不解决就无法验证 ✗
→ 要么装驱动/U 盘蓝牙适配器 ✓ 要么直接用"锁屏兜底"方案（立刻能做 ✓）
