# 测试说明

这些脚本用来验证 WARDEN 是否真的能拦住东西，以及**有没有误伤**。

**★ 建议每次改动之后都跑一遍**，尤其是改了评分逻辑或安全闸的时候。

---

## 环境要求

- Windows 10 / 11
- Python 3.8+（标准库即可，**不需要安装任何第三方包**）
- 已编译的 `WARDEN.exe`

---

## 脚本清单

| 脚本 | 作用 | 需要人工操作 |
| --- | --- | --- |
| `redteam_simulator.py` | 模拟普通流氓软件的恶劣行为（R1~R14） | 否 |
| `redteam_ultra.py` | ★ 专门针对本工具的绕过手段（U1~U10） | 否 |
| `test_ultra.py` | 跑 Ultra 全场景 + 复活流程 | ★ 弹窗需要点 |
| `verify_safety_gate.py` | 验证安全闸（系统进程 / 系统目录 / 普通程序） | 否 |
| `test_selfcheck.py` | 验证启动自校验能检出调包 | 否 |

---

## 怎么跑

### 1. 安全闸测试（最该先跑）

```powershell
python verify_safety_gate.py
```

**这个测试会验证：**
- 20 个系统关键进程 → 必须拒绝强杀 ✓
- 7 个系统目录下的进程 → 必须拒绝强杀 ✓
- 5 个普通程序 → 必须允许 ✓

**期望结果**：32/32 通过

### 2. 红队 Ultra（绕过测试）

```powershell
python test_ultra.py
```

**这会依次跑 10 个场景**，每个场景启动一个模拟器，观察 WARDEN 能不能压住。

**期望结果**：10/10 压制

**★ 其中有两个场景特别重要：**
- **U1 隐藏对抗** —— 被隐藏后立刻又显示出来（直接打"隐藏"这个核心手段）
- **U6 空标题** —— 标题留空，试图绕过标题匹配

### 3. 自校验调包测试

```powershell
python test_selfcheck.py
```

**三步验证：**
1. 未签名版本运行 → 应报"自身未签名"并拒绝运行
2. 签名 + 写入基线 → 应通过
3. ★ 改一个字节 → 应报"被改动过"并拒绝运行

### 4. 授权弹窗流程（需要人工点）

```powershell
python test_ultra.py --only revival
```

**会弹出授权窗口，请按提示操作。**

## ★ 测试的安全约定

这些脚本遵守以下约定 —— 如果你要改它们，**请保持**：

```
1. 只结束【测试自己启动】的进程 ✗
   绝不按名字批量杀进程 ✗
   （早期版本犯过这个错：taskkill /f /im python.exe
     把测试运行器自己也杀了 ✗）

2. 强杀范围由 DSH_SANDBOX_PIDS 环境变量限制 ✓
   WARDEN 只会结束这个列表里的进程 ✓

3. 只操作标题带测试标记的窗口 ✓
   绝不广播 WM_CLOSE ✗
   （早期版本犯过这个错：全局广播把
     TextInputHost / ShellExperienceHost 关掉了，
     导致触摸板手势失灵 ✗）

4. 自清理 ✓
   跑完把模拟器创建的窗口都关掉 ✓
```

## 输出怎么看

**测试脚本会打印统计**，例如：

```
■ U1
  红队已起，可见窗口 = 3
  可见窗口: 起始=3 结束=0
  处置: 隐藏=2  ★L3强杀=1  被拒=0
  → ✓ 压制住
```

**关键看两个数：**
- **可见窗口 结束=0** → 压住了 ✓
- **L3强杀** → 用了强制手段（说明温和手段不够）

**如果出现 `★ 未压住`**，去 WARDEN 的日志里看 `[评分]` 和 `[决策]` 行，
它们会说明**为什么没动手**（分数不够？被安全闸拦了？）
